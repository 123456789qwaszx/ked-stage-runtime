# 블러 — 세 번의 시도와 지금의 선택

## 0. 한 문장

> **배경은 미리 흐려 두고 통째로 바꾼다. 캐릭터는 밉맵을 읽고 네 탭으로 격자를 지운다.**

---

## 1. 왜 이 문서가 있는가

블러를 세 번 만들었고 두 번 버렸다. **버린 이유가 기법의 우열이 아니라 이 저장소의 사정이라서**,
근거를 안 남기면 다음 사람이 같은 길을 다시 판다.

특히 v2를 지우는 커밋은 **1,774줄을 삭제한다.** 그 삭제가 정당한 이유가 여기 있다.

## 2. v1 — 셰이더 다중 탭 (폐기)

캐릭터와 배경에 각각 9탭 블러를 셰이더 그래프로 넣었다.

| 버린 이유 | |
|---|---|
| 품질 | 탭이 성글어 넓게 흐리면 유령상 |
| 비용 | 픽셀당 9회 샘플 |
| **키워드 없음** | 블러를 안 쓸 때도 경로를 탔다. `Branch` 노드는 양쪽을 다 평가하므로 비용이 안 준다 |

> 마지막 항목이 v3에서 `_BLUR` **Boolean Keyword**(Multi Compile)를 쓰는 이유다.
> `shader_feature`는 런타임에만 켜는 변형이 빌드에서 스트립되므로 안 된다.

## 3. v2 — 레이어를 통째로 캡처해서 블러 (폐기)

캐릭터와 배경을 stage/layer 단위로 묶어 1/4 해상도(축당, 픽셀 수로 1/16)로 캡처한 뒤 흐렸다.

**맞았던 것**: 비용이 크게 줄고, 블러 단위가 무대 논리(stage/layer)와 일치했다.

**틀렸던 것 — 이게 결정타다:**

> **착란원(CoC)이 없다.** 레이어 하나를 한 장의 이미지로 만들어 균일하게 흐리면
> 초점이 나간 게 아니라 **카메라 렌즈에 자국이 남은 것처럼** 뿌옇다.
> 커널을 바꿔도 이건 안 고쳐진다. 깊이마다 흐림이 달라야 디포커스로 읽힌다.

곁따라온 것들:

- 코드 복잡도 — `back` / `capture` / `proxy` / `overlay` 개념이 생겼다.
  이 구조는 설계 선택이 아니라 **Screen Space Overlay 캔버스를 카메라가 찍을 수 없다**는
  제약 하나를 우회한 하류 결과물이다.
- **Spine 차단** — 프록시가 `Image`이고 소스에서 `sprite`/`type`/`fillCenter`/`fillMethod`/
  `preserveAspect`/`material`을 복사해 그린다. 여섯 중 다섯이 `Image` 전용이라
  `SkeletonGraphic`은 하나도 갖지 않는다. 스켈레톤을 프록시에 그리려면 별도 경로를 파야 한다.

> **v2는 제거됐다.** `Runtime/ScreenEffect/StageDepthBlur/` 12파일과 `UISeperableBlur.shader`,
> 그리고 `PresentationUIRoot`의 FrostedGlass 오버레이 배선이 전부 빠졌다.
> `IStageDepthContentSlotProvider`만 살아남아 `Runtime/PresentationCore/`로 옮겼다 —
> 이건 블러가 아니라 무대/레이어 슬롯 조회라 리그 슬롯 해석기(`CharRigSlotResolver`)가 계속 쓴다.
> (당시에는 배경 리그의 해석기도 썼다 — 배경 리그는 2026-10-29에 캐릭터 슬롯으로 합쳐졌다.)

### 같은 이유로 배제한 것 — Dual Filter / Dual Kawase

Bjørge, *Bandwidth-Efficient Rendering*, SIGGRAPH 2015 Mobile Graphics (ARM).
가우시안보다 1.5~15배 빠르지만 **다운샘플/업샘플 렌더타깃 체인을 요구한다.**
그게 정확히 v2에서 걷어내려는 배관이다. **기법이 나빠서가 아니라 우리가 지우려는 것을 요구해서** 뺐다.

## 4. v3 (현재) — 요소별 밉 + 5탭

### 배경 — 캐릭터와 같은 셰이더로 (사전 블러 교체는 기각)

처음에는 미리 흐린 에셋을 hardSwap하려 했다. 실측이 그 계획을 뒤집었다:

- 저작이 부르는 값이 **0.8 / 0.9 / 1 / 1.1 / 1.2** 로 연속적이다. 이산 에셋 교체로 재현하려면
  단계를 여러 장 만들어야 한다
- 배경은 **텍스처 한 장**이라 밉 기반이 특히 잘 맞는다
- `CharacterBlur.hlsl`을 그대로 물리면 되므로 **에셋 0장, 새 코드 0줄**이다

그래서 배경도 요소별 셰이더 블러로 간다. 당시에는 별도 배경 리그의 `VisualEffect`가
캐릭터와 같은 `RigVisualEffectController`를 공유했다 — 머티리얼 인스턴스화와
`materialForRendering` 처리는 버그가 잦은 자리라 복제하지 않았다. 2026-10-29부터는 배경이
**캐릭터 리그 그 자체**(캐스팅하지 않은 슬롯)라 공유할 것도 없다 — 같은 컨트롤러 하나다
(재생 저장소 `docs/PLAN_background-as-slot.md`). `focus_on`은 배역 있는 슬롯만 보므로 배경은 여전히 대상이 아니다.

`screen_blur <layer> <amount>`의 의미("그 레이어에 있는 것을 흐린다")는 그대로 두고
기구만 바꿨다(`StageLayerBlurCommand`). far 레이어에는 배경만 있으므로 기존 저작이
그대로 동작하고, 캐릭터를 그 레이어에 올리면 같이 흐려진다.

> ⚠ 배경 텍스처도 `enableMipMap=1` + Trilinear가 필요하다. 6장 전부 꺼져 있었다.
> 대가는 메모리 +33%다.

### 캐릭터 — 밉맵 + 십자 4탭

`Assets/Ked.Presentation/Shaders/CharacterBlur.hlsl`.

**밉맵은 이미 블러다.** 밉 체인은 로드 시점에 박스 필터로 만들어진다 — 레벨 n은 2ⁿ×2ⁿ 영역의 평균이다.
LOD 4를 읽는 것은 16×16 박스 블러를 **1탭**에 얻는 것이고, 메모리는 +33%(1+¼+⅟₁₆+… = 4/3)뿐이다.
게다가 높은 밉은 작아서 텍스처 캐시에 상주한다.

**그런데 밉만으로는 허접하다.** 흐림이 약해서가 아니라 **재구성이 나빠서**다.
LOD 4를 화면에 그리면 8배 확대이고, 이중선형은 값은 연속이지만 **기울기가 텍셀 경계마다 꺾인다.**
사람 눈은 기울기 불연속에 민감해서(마하 밴드) 다이아몬드 격자와 얼룩이 보인다.

**네 탭이 하는 일은 블러가 아니라 재구성 보정이다.** 간격이 밉 텍셀 1.5개라 흐림의 양은 거의 안 는다.
조금씩 어긋난 위치에서 이중선형 결과를 다섯 번 뽑아 평균하면 **꺾임이 서로 다른 위상에서 일어나 상쇄된다.**
MSAA가 계단을 지우는 것과 같은 원리다.

왜 1.5인가:

| 간격 | |
|---|---|
| < 1 텍셀 | 다섯 탭이 같은 이중선형 셀 안 → 상쇄 없음, 효과 없음 |
| **~1.5 텍셀** | 셀 경계를 걸침 → 꺾임이 평균으로 사라짐 |
| > 3 텍셀 | 다섯 개가 따로 보임 → 유령상 |

**⚠ 탭 간격은 `exp2(lod)`에 비례해야 한다.** "1.5텍셀"은 지금 읽는 밉의 텍셀이어야 한다.
원본 기준으로 고정하면 LOD 2에서 실제 0.375밉텍셀이 되어 **4탭이 무력해진다.**

### 출처

Lee, Kim, Choi — *Real-Time Depth-of-Field Rendering Using Anisotropically Filtered
Mipmap Interpolation*, IEEE TVCG 15(3), 2009, pp. 453–464.
<http://cg.skku.edu/pub/papers/2009-lee-tvcg-mintdof-cam.pdf>

밉 보간 DOF의 **세 가지 아티팩트**가 여기서 나온다:

1. **이중선형 확대** — 우리는 4탭으로 고쳤다. 논문의 해법은 *원형* 확대 필터였고 우리는 십자다(더 싸고 덜 정확)
2. **광도 누출** — 초점 영역의 밝기가 흐린 영역으로 샘
3. **블러 불연속** — 선명한 물체와 흐린 배경 경계의 후광

> **②③은 우리에게 발생하지 않는다.** 화면 공간에서 흐릴 때만 생긴다 —
> 합성 후 흐리면 서로 다른 깊이의 픽셀이 한 커널에 섞이기 때문이다.
> 지금은 캐릭터마다 자기 텍스처 공간에서 홀로 흐린 뒤 합성하므로 구조적으로 불가능하다.
>
> **v2를 버리고 요소별로 간 결정이, 가장 싼 블러 기법을 쓸 자격까지 같이 사 왔다.**

화면 공간 DOF 쪽 표준 참고: GPU Gems 3 Ch.28, Hammon, *Practical Post-Process Depth of Field*.

| **보케가 아니다** | 실제 디포커스는 원형 조리개라 밝은 점이 원반이 된다. 박스⊛십자는 그냥 흐려진다. 야경·역광에서 티가 난다 |

## 6. 실측으로 뒤집힌 것들

이 문서를 쓴 뒤 생성된 HLSL(`Library/Artifacts`)을 읽고 확인한 결과, 처음 적었던 세 가지가 틀렸다.

**① 림은 16탭이 아니라 4탭이다.**
외곽 림이 십자 4탭(UV ± `_RimWidth`)을 찍고, 이웃 알파의 `Maximum`에서 자기 알파를 뺀 뒤
`smoothstep(0, _RimSoftness)`를 통과시킨다. 내부 림은 **같은 4탭의 `Minimum`을 재사용**한다.
추가 샘플이 없다. 싸므로 HLSL로 옮길 이유가 없다.

**② 진짜 비쌌던 것은 `_StageBlurEdge*` 12탭이었고, 그건 죽어 있었다.**
v2 캡처 시스템의 경계 처리다. 유일한 writer였던 `StageDepthDefocusCommand`가 사라지면서
`_StageBlurEdgeHide`가 항상 0이 됐고, 셰이더 말단이
`lerp(정상알파, 침식알파, _StageBlurEdgeHide)`라 **12탭 전체가 계산된 뒤 버려지고 있었다.**
제거로 그래프가 166 → 83노드, 픽셀당 샘플이 17 → 5가 됐다.

**③ Keyword는 `#if`가 아니라 삼항 연산자로 방출된다.**
`#pragma multi_compile_local _ _BLUR`로 변형은 진짜 두 개가 생기지만, 분기 자체는
`_BLUR ? A : B`다. Custom Function 호출은 삼항 **바깥**의 독립 문장이라,
블러 경로가 실제로 빠지는지는 **전처리기가 아니라 컴파일러의 죽은 코드 제거에 달렸다.**
알파를 Keyword 안으로 넣은 작업이 이걸 "원천적으로 불가능"에서 "가능"으로 바꿨다.
확실히 하려면 분기를 HLSL 안(`#ifdef _BLUR`)으로 옮기면 되고, 그러면 Keyword 노드 2개와
베이스 샘플이 불필요해진다.

## 7. CoC 정책 — focus_on

```
<<focus_on @1>>            @1에 초점. 나머지는 깊이 차이만큼 흐려진다
<<focus_on @1 0.6>>        최대 흐림 0.6으로 제한
<<focus_on @1 0.6 0.8s>>   0.8초에 걸쳐
<<focus_clear>>            전원 복귀
```

```
coc = saturate(|depthScale_char − depthScale_focus| × falloff) × maxBlur
```

**깊이는 레이어가 아니라 depth 프리셋에서 온다.** 캐릭터는 대부분 `mid` 레이어에 몰려 있고
깊이는 `size` 커맨드로 갈리기 때문에, 레이어를 기준으로 삼으면 전원이 같은 값이 되어
**v2의 실패를 그대로 반복한다.**

그래서 `CharacterRigRefs.SettledDepthScale`을 추가했다. `SetDepthCommandCharR`가 목표값을
확정할 때 기록하므로 **트윈이 도는 중에도 "끝나면 어디인가"** 를 들고 있다 — 정지 프레임 원칙.
열거형이 아니라 스케일 값인 이유는 `useLevel=true` 경로에 프리셋 키가 없고, 공식이 필요로 하는
것도 스케일이기 때문이다.

`falloff` 기본값 1.43은 depthScale 범위(Far 0.68 ~ Close 1.38, 간격 0.70)의 역수다 —
무대 양 끝이 최대로 흐려진다.

배경은 대상이 아니다. `screen_blur far`가 이미 레이어 단위로 처리한다.

### ⚠ 블러를 쓰는 커맨드가 셋이다

`focus_on` · `screen_blur` · `char_visual_focus/defocus`(프리셋의 `blur` 필드)가 모두
같은 `_BlurAmount`를 쓴다. 서로 죽이지 않으므로 **동시에 걸면 매 프레임 싸운다.**

재발행만은 막아 두었다 — 트윈 타깃을 커맨드 인스턴스가 아니라 공유 스코프로 잡는다:

| 커맨드 | 트윈 타깃 |
|---|---|
| `focus_on` | `CharacterRigRegistry` (모든 캐릭터) |
| `screen_blur` | 레이어의 content root |
| `char_visual_*` | 해당 리그의 컨트롤러 |

같은 커맨드를 다시 걸면 이전 트윈이 죽는다. **다른 커맨드끼리는 여전히 겹칠 수 있다** —
저작에서 한 번에 하나만 쓰는 것이 전제다.
